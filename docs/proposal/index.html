なぜこの領域を選んだのか

  1. 自身が現役美容師であり、実際の営業中の利用場面を具体的に想定できることから、予約管理機能を選びました。

  2. 自分がサービスを導入する際、特に重視するのは、お客様が予約した後の管理業務です。予約内容や施術に必要な情報を素早く確認できるか、営業中でも迷わず操作できるかという視点で、改善点を検討しました。

  3. また、予約を受けた後の日々の運用に加え、導入時の予約画面の構築にも着目しました。初めて利用する際の設定から、営業中の確認・記録まで、事業を滞りなく進められる予約管理を目指しています。

01
改善予約一覧

予約詳細へのアクセス改善

【課題分析】

現行のUIでは、予約一覧のテーブル幅が画面幅を超えており、詳細ボタンが画面外に見切れています。予約詳細を確認するたびに横スクロールが必要となるため、ボタンを見つけづらく、一覧確認時の操作負担が生じます。

【提案内容】

予約詳細を開くリンクを、詳細ボタンから一覧のお客様名へ移しました。画面内に表示されているお客様名から、その行の予約詳細モーダルを直接開けるようにすることで、横スクロールの手間を省き、予約情報へ素早くアクセスできる設計にしました。

02
メイン提案機能追加予約詳細お客様メモ

予約詳細とお客様メモの連携

【課題分析】

現行の予約詳細では、予約内容や予約時の回答情報を確認できますが、施術に関する記録を同じ画面から参照する導線がありません。施術情報を別の管理ソフトなどで確認する運用では、画面の切り替えやお客様の検索し直しが必要となり、確認に時間がかかります。

【提案内容】

予約詳細モーダルに「お客様メモ」ボタンを設置し、1:1チャットで使用されているメモを直接開けるようにしました。予約確認から施術情報の参照までを一連の操作で行えるようにし、画面の切り替えやお客様の検索し直しを減らすことで、営業中の作業を中断しにくい設計にしました。

期待効果施術者がお客様を探し直す手間が減り、施術前の確認が早くなります。その結果、お客様をお待たせする時間の短縮にもつながります。

AI活用プロセス

使用ツール：ChatGPT Work

  1. 自分で考えたこと

    予約を確認するときに、お客様のカルテ（施術の記録）も一緒に見られるとスムーズだと感じた。そこで、予約詳細モーダルから「お客様メモ」を開けるようにする。

  2. AIへの指示

    このモーダルの（予約履歴）ボタンの左横に同じ大きさ＆アイコンは変えて（お客様メモ）を新設しようと思います。（中略）カルテが別のタブにあると、お客様を探し直す手間もあるので、予約カレンダーの名前をタップするだけでカルテも一緒に出せるのは施術者やお客様の時短にも繋がると思いました。ボタンの位置と大きさまで具体的に伝えたうえで、美容室などのサロンでなぜ必要なのか、現場目線の理由も添えて相談しました。

  3. AIの回答

    実装は可能。「お客様メモ」を押すと、予約に紐づくお客様のメモを同じパネル内に表示できる。

    • 1:1チャットの既存のメモを、予約詳細から閲覧・編集できるようにするのが現実的。写真や施術日などを記録する専用カルテを新設する場合は、バックエンドの追加開発が必要
    • 配置（予約履歴の左横・同じ大きさ・メモ帳や鉛筆のアイコン）は問題なし。狭い画面では2段にする
    • 注意点：既存メモと別々に保存すると内容が食い違うため、どちらの画面から開いても同じメモを表示・更新する設計にする

  4. 結果

    採用：既存メモとの連携（専用カルテは新設しない）。美容室専用のカルテになってしまうのを避けるため。また、メモが複数の種類に分かれると、ユーザーがどれを使えばよいか迷うため。採用：どちらの画面から開いても同じメモを表示・更新する設計。開く画面によって内容が違うといった混乱が起きないため。汎用性の高い既存のデザインはそのまま活かし、施術カルテとしても使えるよう、年ごとの移動やピン留めなどの機能を追加しました。対象外：狭い画面での2段表示。今回はデスクトップ向けのプロトタイプのため、iPadなどからの利用は想定から外しました。

03
機能追加お客様メモ

過去のメモを年ごとにたどれる機能

【課題分析】

現行のメモは、長期利用によって記録が蓄積すると、過去のメモを確認するために長いスクロールが必要となり、目的の情報を見つけにくくなります。

【提案内容】

お客様メモの上部に、年を選べるプルダウンを設置しました。年を選ぶと、その年の見出しまで一覧が移動します。ほかの年のメモも残したまま表示するため、前後の施術の流れを続けて読むことができ、長いスクロールをせずに過去の施術記録を素早く確認できる設計にしました。

04
改善お客様メモ

メモの新規作成ボタンの明確化

【課題分析】

現行では、メモの新規作成がアイコンのみで表示され、周囲にも複数のアイコンが並んでいます。そのため、操作に不慣れなユーザーは、メモを追加する操作を見つけるまでに迷う可能性があります。

【提案内容】

アイコンのみの表示を、テキストラベル付きの「＋新規作成」ボタンに変更しました。アクセントカラーで主要な操作として強調し、視認性と操作の発見性を向上させることで、初めて利用するユーザーも迷わずメモの作成を始められる設計を目指しました。

05
仕様変更お客様メモ

メモ作成時の入力負担の軽減と誤操作の防止

⑤-1 保存に必要な入力条件の見直し

【課題分析】

現行のメモ作成では、タイトルと本文の両方を入力しないと保存できないため、営業中など、短時間で情報を記録したい場面で入力の負担が生じます。

【提案内容】

タイトル・本文のいずれかが入力されていれば保存できる仕様に変更しました。短い備忘録も必要な情報だけで記録できるようにし、営業中の入力負担を軽減します。

⑤-2 未保存の入力内容を保護する確認ダイアログ

【課題分析】

現行では、未保存の状態で「×」を押すと、確認なく入力内容が破棄されるため、誤操作による情報の消失や、再入力の負担が生じます。

【提案内容】

未保存の変更がある状態でモーダルを閉じる際に、保存・破棄を選択する確認ダイアログを表示する仕様にしました。閉じる前に入力内容の扱いを確認できるようにし、意図しない破棄を防ぐ設計にしました。

06
機能追加お客様メモ

重要なメモのピン留め機能

【課題分析】

現行のメモには並び替え機能がありますが、重要な情報や定期的に参照するメモを上部に維持するには、手作業で表示順を調整する必要があります。

【提案内容】

各メモにピン留め機能を追加し、ワンクリックで一覧上部に固定できるようにしました。表示順を調整する負担を減らし、施術時の注意事項やお客様の希望など、繰り返し確認したい情報へ素早くアクセスできる設計にしました。

07
メイン提案機能追加予約設定

予約の流れを体験できるリアルタイムプレビュー

【課題分析】

現行では、プレビューが設定画面とは別の単体表示となっているため、入力内容を確認するたびに「設定画面」と「プレビュー」を切り替える必要があります。特に管理画面の操作に不慣れなユーザーは、設定内容がお客様側の画面にどう反映されるかを把握しづらく、確認に手間がかかります。

【提案内容】

設定画面の右側に、入力内容をリアルタイムに反映するプレビューを設置しました。画面を切り替えずに設定結果を確認できるようにし、編集と確認の往復を減らします。また、お客様側の画面や予約の流れを確認しながら設定できるため、初めて構築するユーザーも、実際の利用場面をイメージしながら作業を進められる設計にしました。

AI活用プロセス

使用ツール：ChatGPT Work

  1. 自分で考えたこと

    予約ページを実際に構築していく中で、お客様側の流れが見えないと全体のイメージがつかめず、手が止まりがちだった。そこで、同じ画面内にプレビューがあると良いと考えた。

  2. AIへの指示

    同じ画面上に（右側）リアルタイムプレビューがあれば、自分が今どこの部分の構築を、なんのためにやっているのか理解しやすく（中略）お客様の気持ちになって要素を配置できると思いました。（中略）リアルタイムプレビューを設置する事で何度も構築している代行業者ではなく、初めて設定する事業者がより進みやすく、設定途中で離脱しにくいのもポイントです。自分自身が予約ページの構築で流れを把握しづらかった体験と、「事業者が自分で構築できる」というエルメの強みをもとに、誰のための機能なのかを明確にして相談しました。

  3. AIの回答

    実装は可能。「ボタンを押して確認する方式から、編集しながら右側で常時確認できる方式への改善」と整理すると明確。

    • おすすめは、編集内容が即時反映され、仮の予約操作で流れを確認できるプレビュー（編集中の質問を強調、「戻る」「次へ」で流れを確認、サンプルデータは明記、実予約・決済・通知は発生させない）
    • 注意点：そのまま追加すると編集欄が狭くなるため、左ナビの折りたたみやプレビューの開閉で横幅を調整する
    • 設定途中の離脱が減るかは検証が必要だが、仮説として妥当

    自分の返答「プレビュー画面はあるのですが、その設定単体の画面となるので『体験』は得られず。画面単体だけではなく、ページ遷移も含めた流れを把握する事がポイントかなと思います。」

  4. 結果

    採用：保存前の内容もリアルタイムに反映する仕様。AIは「まずは保存後に更新」から始める段階案を示しましたが、編集しながらその場で予約者の体験を確かめることが目的のため、リアルタイム反映まで実装しました。採用：最初の画面から予約完了まで、画面を進んだり戻ったりできるプレビュー。採用：AIが提案した名前「予約の流れを体験できるリアルタイムプレビュー」。目的が伝わりやすいため、項目のタイトルにしました。既存機能で対応：プレビューを置くと編集欄が狭くなる問題。現行の左ナビがもともと折りたたみ・開閉できる仕様のため、それを活かしました。

対話の続き

  1. AI

    「設定結果の見た目」だけでなく、「お客様が予約を完了するまでの流れ」を確認できることがポイントだと捉え直した。コース選択 → スタッフ選択 → 日時選択 → 質問入力 → 内容確認 → 完了を、プレビュー内で進んだり戻ったりできる仕様を提案。

    自分の返答で、AIの理解が「単体の画面」から「予約の流れ」へ変わった
  2. 自分
    「デスクトップ画面右上にある『予約カレンダーを見る』が全体プレビューのようなものになっているのですが、現状はモーダルを開いた後に、他の設定を編集しようとするとモーダルが閉じてしまうため、このモーダルを開いたまま編集ができると良いのですが」
  3. AI

    実装可能。ただし画像を見る限り、これはモーダルではなく別ウィンドウで開いた予約画面で、編集画面をクリックすると後ろに隠れている可能性がある。予約画面を管理画面の右側に固定表示するパネルにすれば、編集と確認を並行できる。まずは「常時表示＋保存後に更新」、次にリアルタイム反映と段階を分けられる。

  4. 自分
    「確かに！モーダルではなく、別ウィンドウだったので、他の編集ボタンを押したら後ろに隠れちゃってたんですね。新しく作り直すより、このウィンドウが常に開いたままであれば、プレビュー画面と編集画面を行ったり来たりしなくて良いのでいいですね！」
  5. AI

    既存の予約画面を活用できれば、改善範囲を絞れる。ただし、別ウィンドウを常に最前面に固定することはWebサイト側からは保証できず、編集ボタンを覆う恐れもある。既存の予約画面を管理画面の右側に組み込み、編集画面と並べて表示する形が適している。

    既存の「予約カレンダーを見る」を活かし、新しく作らずに改善範囲を絞る方向が決まった

AI Process

AI活用のまとめ

課題の発見と機能の発案は、実際のサロンワークを想定して自分で行いました。そのうえで、実装可能性の相談や文章の整理はChatGPT Work、プロトタイプの実装はCursorに任せ、役割を分けて進めました。

AIに任せたこと

  • プロトタイプの実装（Cursor）
  • エルメの機能調査、競合比較、改善テーマの候補出し（ChatGPT Work）
  • 改善案の実装可能性の相談、提案文章の整理、Cursorへの指示文の下書き（ChatGPT Work）
  • 提案ドキュメントのWebページ制作（Claude Code）

自分で考えたこと

  • サロンで働く人を想定し、予約を受けてからお客様が来店されるまでの作業工数の短縮を目的とした、機能の改善と追加
  • 実際のサロンワークを想定して機能を触り、手が止まった箇所や迷いが出た箇所を見つけた
  • 手を動かしていく中で、「こういう機能があればもっと効率的だ」と感じた機能を挙げていった
